# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

xv6 is a re-implementation of Unix Version 6 for modern RISC-V multiprocessors, written in ANSI C. It's primarily used as a teaching operating system for MIT's 6.1810 course. The codebase prioritizes simplicity and clarity over features.

## Build and Test Commands

### Building
```bash
# Build the kernel
make kernel/kernel

# Build the filesystem image
make fs.img

# Clean all build artifacts
make clean
```

### Running
```bash
# Run xv6 in QEMU (requires RISC-V toolchain and qemu-system-riscv64)
make qemu

# Run with GDB support (start GDB in another terminal)
make qemu-gdb

# Specify number of CPUs (default is 3)
make qemu CPUS=4
```

### Testing
```bash
# Run all user tests
./test-xv6.py usertests

# Run quick tests
./test-xv6.py -q usertests

# Run specific test by name or regex
./test-xv6.py <test-name>
```

## Architecture

### Directory Structure
- **kernel/**: All kernel code and headers
- **user/**: User-space programs and libraries
- **mkfs/**: Filesystem creation utility

### Kernel Architecture

#### Process Management (kernel/proc.c, kernel/proc.h)
- Process states: UNUSED, USED, SLEEPING, RUNNABLE, RUNNING, ZOMBIE
- Each process has a `struct proc` containing:
  - Page table (`pagetable_t`)
  - Trapframe for saving user registers during traps
  - Context for kernel thread switching
  - Open file descriptors array
  - Current working directory
- Maximum 64 processes (NPROC)
- Supports up to 8 CPUs (NCPU)

#### Memory Management (kernel/vm.c, kernel/kalloc.c)
- **Virtual Memory**: Separate page tables for kernel and each user process
- **Memory Layout** (kernel/memlayout.h):
  - Kernel starts at physical address 0x80000000 (KERNBASE)
  - User processes have memory layout: text → data/bss → stack → heap → TRAPFRAME → TRAMPOLINE
  - TRAMPOLINE page is at highest virtual address (MAXVA - PGSIZE), shared by kernel and user
  - Kernel stacks are beneath trampoline, each surrounded by guard pages
- **Physical Memory**: Simple free-list allocator in kalloc.c

#### System Calls (kernel/syscall.c, kernel/syscall.h)
- Syscalls are invoked via RISC-V `ecall` instruction
- User-space stubs generated by `user/usys.pl` Perl script → `user/usys.S`
- Syscall number passed in register a7
- Arguments retrieved using `argint()`, `argaddr()`, `argstr()` functions
- Add new syscalls by:
  1. Adding number to kernel/syscall.h
  2. Adding entry to user/usys.pl
  3. Implementing handler in kernel/sysproc.c or kernel/sysfile.c
  4. Adding function pointer to syscalls[] array in kernel/syscall.c
  5. Adding prototype to kernel/defs.h and user/user.h

#### Trap Handling (kernel/trap.c, kernel/trampoline.S)
- Trampoline code handles user↔kernel transitions
- Trapframe structure saves/restores all user registers
- Separate trap vectors for kernel (kernelvec.S) and user (trampoline.S)
- Interrupts include timer ticks, device interrupts (UART, disk), and system calls

#### File System (kernel/fs.c, kernel/bio.c, kernel/log.c)
- **On-disk layout**: boot block | superblock | log | inode blocks | free bitmap | data blocks
- **Logging**: Write-ahead logging for crash recovery (kernel/log.c)
  - Use `begin_op()` before filesystem operations
  - Use `log_write()` instead of `bwrite()` for logged writes
  - Use `end_op()` to commit transaction
- **Inodes**: Maximum 50 active in-memory inodes (NINODE)
- **Buffer cache**: 30 buffers (NBUF) for disk blocks
- **Block size**: 1024 bytes (BSIZE)
- **File size limit**: 12 direct blocks + 256 indirect = 268 blocks max

#### Locking
- **Spinlocks** (kernel/spinlock.c): For short critical sections, disable interrupts
- **Sleep-locks** (kernel/sleeplock.c): For longer operations that may sleep (e.g., disk I/O)
- Process lock (`p->lock`) must be held when accessing process state
- Lock ordering to prevent deadlock is critical

#### Devices
- **UART** (kernel/uart.c): Serial console at 0x10000000
- **virtio disk** (kernel/virtio_disk.c): Block device at 0x10001000
- **PLIC** (kernel/plic.c): Platform-level interrupt controller at 0x0c000000

### Assembly Files
- **kernel/entry.S**: Entry point when kernel boots
- **kernel/trampoline.S**: User/kernel trap handling and context switching
- **kernel/swtch.S**: Kernel thread context switching
- **kernel/kernelvec.S**: Kernel trap vector

### User Programs
- Built from user/*.c files, linked with user library (ulib.o, usys.o, printf.o, umalloc.o)
- Each program becomes a separate executable prefixed with underscore (e.g., `_ls`)
- Standard programs: sh (shell), ls, cat, grep, wc, init, usertests, etc.

## Development Notes

### Toolchain Requirements
- RISC-V "newlib" toolchain (riscv64-unknown-elf-* or riscv64-linux-gnu-*)
- QEMU compiled for riscv64-softmmu (minimum version 7.2)

### Compiler Flags
- `-march=rv64gc`: RISC-V 64-bit with GC extensions
- `-ffreestanding`: Freestanding environment (no standard library)
- `-fno-omit-frame-pointer`: Keep frame pointers for debugging
- Many `-fno-builtin-*` flags to avoid built-in function optimizations

### Constants (kernel/param.h)
- NPROC=64: Max processes
- NCPU=8: Max CPUs
- NOFILE=16: Open files per process
- NFILE=100: Open files system-wide
- MAXARG=32: Max exec arguments
- MAXPATH=128: Max file path length

### Code Style
- Follows Unix v6 style: simple, readable, educational
- Function names often prefixed by subsystem (e.g., `uvm*` for user VM, `kvm*` for kernel VM)
- Internal kernel functions often prefixed with 'k' (e.g., `kfork`, `kexit`, `kkill`)

## Common Pitfalls

1. **Locking**: Always respect lock ordering. Process lock must be held when accessing p->state, p->chan, p->killed
2. **Virtual Memory**: Remember user and kernel have separate page tables; use `copyout()`/`copyin()` to transfer data
3. **Logging**: Filesystem operations must be wrapped in `begin_op()`/`end_op()` and use `log_write()`
4. **Interrupts**: Spinlocks disable interrupts; don't hold them while sleeping
5. **Assembly**: RISC-V calling convention uses a0-a7 for arguments, a0-a1 for return values
